# 🛠️ Time Tracker Bot: Backend Documentation

Данный проект представляет собой систему учета рабочего времени сотрудников, построенную на базе **Telegram Bot API**, **FastAPI** и **Google Sheets API**.

## 🏗️ Архитектура системы

Система состоит из трех независимых, но взаимодействующих компонентов:

1.  **Telegram Bot (`main.py`)**: Управляет взаимодействием с пользователем в мессенджере, командами управления и первоначальной авторизацией.
2.  **Webhook Server (`webhook_server.py`)**: FastAPI сервер, обрабатывающий данные от WebApp (фронтенда), управляет логированием в таблицы и маршрутизацией уведомлений в группы.
3.  **Google Sheets Integration (`sheets_manager.py`)**: Инкапсуляция всей логики работы с Google Sheets и Drive (хранение данных, управление пользователями, создание ежемесячных отчетов).

## 🔐 Процесс аутентификации и идентификации

Проект использует многоуровневую систему определения личности пользователя:

### 1. Middleware в Telegram Боте (`AuthMiddleware`)
Каждое сообщение в боте проходит через слой авторизации, который:
*   Проверяет Telegram ID во внутреннем кэше (`USER_CACHE_ID`).
*   Если ID не найден, пробует сопоставить `username` пользователя с базой.
*   **Auto-binding**: Если найден маппинг по `username`, система автоматически записывает Telegram ID пользователя в Google Таблицу и обновляет кэш.
*   Если пользователь не идентифицирован, он переводится в статус **Orphan** (предлагается привязка аккаунта).

### 2. Безопасность WebApp (`initData` validation)
Запросы от WebApp к Webhook серверу подписываются хешем (`HMAC-SHA256`) на стороне Telegram. Сервер (`webhook_server.py`) выполняет:
*   Проверку подлинности данных через `verify_telegram_data`.
*   Секретный ключ для HMAC генерируется из `BOT_TOKEN`.
*   Это гарантирует, что запросы приходят именно от легитимного клиента WebApp, запущенного внутри Telegram.

## 📑 Процессы Google Sheets (Backend Logic)

### 📁 Структура хранения
Система использует Master Template для создания ежемесячных файлов.
*   **Master Sheet**: Содержит вкладку `Config_Users` (реестр сотрудников).
*   **Monthly Sheets**: Файлы вида `Timesheet_Month_Year`, создаваемые в папках подразделений ("Цех" или "Офис").

### 🔄 Автоматизация листов
При первом обращении в новом месяце `GoogleSheetManager`:
1.  Копирует Master Template в папку соответствующего отдела.
2.  **Header Sync**: Обновляет даты в строке 1 вкладки `Отчет_Месяц` (31 день, по 3 колонки на день).
3.  **User Sync**: Из Master-листа переносятся только сотрудники, относящиеся к данному отделу (`team`).
4.  **Logging**: Все отметки записываются во вкладку `DB_Logs` (Date, Time, Name, Action, Submitter).

## 📸 Процесс Check-in / Check-out

Основной рабочий процесс при совершении отметки:

1.  **Запуск**: Команда `/setup_checkin` генерирует URL для MiniApp с токеном `webhook_server_url` и `chat_id`.
2.  **Загрузка данных**: WebApp делает GET-запрос к `/api/config`, получая список сотрудников (для Supervisor) или данные текущего пользователя.
3.  **Фото-фиксация**: Фотография конвертируется в Base64.
4.  **Обработка данных**:
    *   WebApp отправляет POST-запрос на `/api/checkin` (или `/api/upload` + `tg.sendData` в зависимости от реализации).
    *   Сервер декодирует фото.
    *   **Google Sheets Log**: Вызывается `append_log`, который находит (или создает) текущий лист и вставляет новую строку.
5.  **Маршрутизация (Routing)**:
    *   На основе поля `team` сотрудника выбирается целевой `GROUP_ID` из `.env` (`WORKSHOP_GROUP_ID` или `OFFICE_GROUP_ID`).
    *   Для сотрудников офиса добавляется хештег соответствующего департамента (`#бухгалтерия`, `#продажи` и т.д.).
6.  **Уведомление**: Отправляется сообщение с фото в Telegram группу через прямой вызов Bot API.

## ⚙️ Ролевая модель (Backend Perspective)

*   **Employee**:
    *   ID привязан к ФИО. 
    *   Может отправлять данные только за себя (`target_user_id` отсутствует или равен собственному).
*   **Supervisor**:
    *   Имеет доступ к полному списку активных сотрудников отдела.
    *   В запросе к API передает `target_user_id` (ФИО выбранного сотрудника).
    *   В логи записывается и исполнитель, и подтверждающий («Подтвердил бригадир: ...»).
*   **Orphan**:
    *   Telegram ID отсутствует в таблице.
    *   WebApp отображает экран `claim`, позволяя выбрать свое ФИО из списка неактивированных сотрудников.
    *   После выбора вызывается `/api/claim`, который выполняет `bind_telegram_id` в Google Sheets.

## 🔧 Технический стек и зависимости

*   **Python 3.10+**
*   **aiogram 3.x**: Асинхронная библиотека для Telegram Bot.
*   **FastAPI & Uvicorn**: Веб-сервер для обработки хуков и API.
*   **gspread & google-api-python-client**: Работа с Google Sheets и Drive.
*   **httpx**: Асинхронные HTTP запросы.
*   **Nginx**: Reverse proxy с SSL termination (production).
*   **Systemd**: Управление сервисами на VPS (production).

## 🚀 Развертывание на VPS

Система поддерживает два режима работы:

### Development (Cloudflare Tunnel)
*   Локальный запуск с проксированием через Cloudflare Tunnel
*   Быстрое тестирование без настройки VPS

### Production (VPS + Nginx)
*   Полноценное развертывание на VPS
*   Nginx как reverse proxy с SSL
*   Systemd для автоматического запуска сервисов
*   **Автоматическая очистка фото** с TTL 5 минут

#### Ключевые особенности production:

1. **Двухуровневая очистка фото**:
   - Немедленное удаление после успешной отправки в Telegram
   - Фоновая задача удаляет фото старше 5 минут (на случай ошибок)

2. **Systemd сервисы**:
   - `timetracker-bot.service` - Telegram бот
   - `timetracker-webhook.service` - FastAPI webhook сервер

3. **Мониторинг**:
   - Health check скрипт
   - Автоматическое резервное копирование
   - Логирование через journald

**Быстрый старт**: См. [`deploy/README.md`](deploy/README.md) для полной инструкции по развертыванию.

**Технический план**: См. [`Technical Deployment plan.md`](Technical%20Deployment%20plan.md) для детального технического описания.

## 🛠️ Переменные окружения (.env)

```env
BOT_TOKEN=...          # Токен бота от BotFather
GOOGLE_JSON_PATH=...   # Путь к JSON-файлу Service Account
DRIVE_FOLDER_ID=...      # Корневая папка проекта на Диске
TEMPLATE_FILE_ID=...     # ID мастер-шаблона таблицы

# Настройки групп
WORKSHOP_GROUP_ID=...  # Группа для "Цеха"
OFFICE_GROUP_ID=...    # Группа для "Офиса"

# Настройки WebApp
WEBAPP_URL=...         # URL хостинга MiniApp (например, GitHub Pages)
WEBHOOK_SERVER_URL=... # URL Cloudflare туннеля (или домен VPS)
```

## 📋 Команды управления

*   `/start` — Инициализация, установка кнопок меню.
*   `/setup_checkin` — Генерация закрепленного сообщения с кнопкой терминала.
*   `/update` — Принудительное обновление кэша пользователей в оперативной памяти из Google Таблиц.
*   `/id` — Получение ID текущего чата/пользователя.
