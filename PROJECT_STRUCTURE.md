# 🏗️ Архитектура и структура проекта Time Tracker Bot (v10.0)

> **Дата последнего обновления:** 26.01.2026
> **Статус:** Production Ready (Self-hosted на VPS)

---

## 🎯 Обзор системы

Проект представляет собой профессиональную систему учета рабочего времени, работающую в экосистеме Telegram. Система полностью автономна, развернута на собственном VPS и использует Google Sheets в качестве масштабируемой базы данных и интерфейса отчетности.

---

## �️ Технологический стек

### Backend (Серверная часть)
- **Python 3.10+**: Основной язык разработки.
- **Aiogram 3.x**: Асинхронный фреймворк для взаимодействия с Telegram Bot API.
- **FastAPI / Uvicorn**: Высокопроизводительный веб-сервер для обработки данных из WebApp.
- **Google API Client / GSpread**: Интеграция с таблицами и диском.
- **Httpx**: Асинхронные HTTP-запросы (включая очистку фото).

### Frontend (User Interface)
- **Vanilla JS / HTML5 / CSS3**: Легкий и быстрый фронтенд MiniApp.
- **Telegram WebApp SDK**: Глубокая интеграция с интерфейсом мессенджера.
- **Camera API**: Захват фотографий непосредственно в браузере.

### Инфраструктура (DevOps)
- **Nginx**: Реверс-прокси, SSL-терминация и хостинг фронтенда.
- **Certbot (Let's Encrypt)**: Автоматическое управление SSL-сертификатами.
- **Systemd**: Управление жизненным циклом процессов (автозапуск, логирование).
- **SQLite (Local Cache)**: Внутренний механизм кэширования в памяти для минимизации запросов к Google Sheets.

## �📂 Подробная структура файлов

### 🏠 Корневая директория
- **`main.py`** — Сердце бота. Управляет командами, авторизацией и отправкой отчетов в группы.
- **`webhook_server.py`** — API-сервер. Принимает Base64 фото, сохраняет их и запускает фоновые задачи очистки.
- **`sheets_manager.py`** — Логический слой данных. Инкапсулирует работу с Google Sheets (логирование, кэширование, создание листов).
- **`.env`** — Центральный файл конфигурации (секреты, ID групп, ссылки).
- **`requirements.txt`** — Список всех зависимостей проекта.

### 🌐 Frontend (теперь на VPS)
Файлы находятся в `/home/botuser/time-tracker/www/` и раздаются через Nginx:
- **`index.html`** — Структура интерфейса с шаблонами для Employee, Supervisor и Orphan.
- **`app.js`** — Логика фронтенда: работа с камерой, ролевая модель, отправка данных.
- **`theme.css`** — Премиальный дизайн в стиле Glassmorphism.

### 🚀 Директория `deploy/` (Infrastructure as Code)
- **`nginx/timetracker.conf`** — Конфигурация Nginx (Proxy Pass на FastAPI + статика).
- **`systemd/`** — Описания сервисов для Linux:
  - `timetracker-bot.service`
  - `timetracker-webhook.service`
- **`scripts/`** — Инструменты автоматизации:
  - `deploy.sh` — Скрипт полного развертывания одной командой.
  - `healthcheck.sh` — Мониторинг ресурсов и статуса сервисов.
  - `backup.sh` — Создание резервных копий критических данных.

## ⚙️ Ключевые алгоритмы и логика

### 1. Алгоритм Авторизации (Smart Auth)
Система минимизирует ручную регистрацию за счет двухступенчатой проверки:
1. **По ID**: Проверка Telegram ID в локальном кэше (обновляется из Sheets).
2. **По Username (Auto-bind)**: Если ID не найден, система ищет сотрудника по `@username`. Если находит — автоматически "привязывает" его Telegram ID в таблицу и пускает в систему.
3. **Orphan Flow**: Если пользователь не найден ни по ID, ни по Username, WebApp предлагает форму выбора ФИО из списка "свободных" сотрудников.

### 2. Жизненный цикл фотографий (Double-Cleanup)
Фотографии не занимают место на диске постоянно:
- **Уровень 1 (Немедленный)**: Сразу после того, как `main.py` успешно отправил фото в Telegram группу, он посылает DELETE-запрос на Webhook сервер для удаления файла.
- **Уровень 2 (Фоновый TTL)**: В `webhook_server.py` работает фоновая задача (через `asyncio`), которая раз в минуту сканирует папку `photos/` и удаляет любые файлы старше 5 минут. Это "страховка" на случай сбоев.

### 3. Ролевая модель в MiniApp
- **Employee**: Видит только кнопку захвата фото. Может отмечаться только за себя.
- **Supervisor**: Видит выпадающий список всех активных сотрудников своего подразделения. Делает фото-подтверждение за выбранного человека.
- **Orphan**: Режим привязки аккаунта.

### 4. Роутинг отчетов (Department Routing)
Бот анализирует поле "Отдел" (Цех/Офис) в таблице и пересылает сообщение:
- **Цех** -> В группу цеха.
- **Офис** -> В группу офиса с добавлением хэштега отдела (`#бухгалтерия`, `#продажи`).

## � Структура Google Sheets

Система использует динамическую структуру таблиц:
1. **Master Sheet (Registry)**:
   - `Config_Users`: Список сотрудников (ФИО, Роль, Отдел, TG ID).
2. **Monthly Files**:
   - Автоматически создаются в начале месяца.
   - `Отчет_Месяц`: Матрица посещаемости (Даты, ФИО, Часы).
   - `DB_Logs`: "Черный ящик" системы. Каждая отметка записывается сюда в сыром виде (Дата, Время, Исполнитель, Подверждающий, Ссылка на фото).

## � Безопасность и надежность

1. **Валидация Telegram**: Каждый запрос к API проверяется через `HMAC-SHA256` по секретному ключу бота. Подделать отчет извне невозможно.
2. **Nginx Security**: Закрыты все порты, кроме 80/443. Используются заголовки безопасности (X-Frame-Options и др.).
3. **Авто-рестарт**: При падении Python-процесса, Systemd перезапускает его в течение 5 секунд.
4. **Изоляция**: Бот работает от ограниченного пользователя `botuser`, не имеющего доступа к системным файлам root.
